## PR Summary

This pull request addresses a regression in the OpenTelemetry Python SDK where the `RANDOM_TRACE_ID` flag is set on every span, including those that continue an existing trace ID. The issue arises because the SDK consults the configured ID generator for every new span, which causes child spans to advertise `RANDOM_TRACE_ID` even when they inherit a trace ID from an incoming parent.

The changes in this pull request ensure that the `RANDOM_TRACE_ID` flag is only set when the tracer generates a new root trace ID. For child spans, the SDK preserves the parent's `random_trace_id` bit if it exists. This fix addresses the regression by ensuring that child spans do not inadvertently carry the `RANDOM_TRACE_ID` flag.

The pull request includes:
- A test suite to verify that the behavior has been fixed.
- A changelog entry for the trace propagation fix.
- Documentation updates to reflect the changes in behavior.

This change is important for maintaining compatibility with Level-1 APM backends and homegrown collectors, as it ensures that spans are correctly identified as sampled without unnecessary flags.
