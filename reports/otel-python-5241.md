## PR Summary

This pull request addresses a regression in the OpenTelemetry Python SDK where the `RANDOM_TRACE_ID` flag is set on every span, including those that continue an existing trace ID. The issue arises because the SDK consults the configured ID generator for every new span, which causes child spans to advertise `RANDOM_TRACE_ID` even when they inherit a trace ID from an incoming parent.

The change in this pull request ensures that the `RANDOM_TRACE_ID` flag is only set when the tracer generates a new root trace ID. For child spans, it preserves the parent's `random_trace_id` bit if available, preventing unnecessary flags from being advertised.

Key files and functions touched:
- `opentelemetry-sdk/src/opentelemetry/sdk/trace/__init__.py`: Contains the logic for starting spans.
- `opentelemetry-sdk/tests/trace/test_trace.py`: Includes tests to verify the behavior of child span creation with different parent trace flags.

Notable behavioral changes:
- Child spans now preserve the parent's `random_trace_id` bit, preventing unnecessary flags from being advertised.
- The pull request includes regression coverage for child spans from remote parent contexts with both unset and set random bits.
- A towncrier changelog fragment is added to document this trace propagation fix.
